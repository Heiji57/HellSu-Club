# 구현 계획

각 Phase는 테스트를 통과해야 끝난다. Phase가 끝날 때마다 구현 내용, 변경 파일, 테스트 결과, 남은 작업을 정리한다.

## Phase 1. 기반 구축 — ✅ 완료 (2026-11-05)
- `pyproject.toml`(uv), `.env.example`, `.gitignore`, `Dockerfile`, `docker-compose.yml`(PostgreSQL 17)
- `app/core`: config, database(async engine/session), clock, week, exceptions
- Alembic 설정과 `member`, `audit_log` 모델·마이그레이션
  - 계획 변경: `audit_log`를 Phase 2에서 앞당겼다. 회원 상태 변경도 감사 기록 대상이기 때문이다.
- 봇 기동, 길드 명령 동기화, 역할 확인(`bot/checks.py`)
- 역할 기반 회원 동기화: `on_member_update`, `on_member_remove`, 시작 시 동기화
- `/도움말`, `/관리 시스템상태`(봇·DB 상태만)

**완료 조건:** 봇이 실행되고 DB에 연결된다. 회원 역할을 부여하거나 회수하면 `member`가 ACTIVE/INACTIVE로 바뀐다.
**테스트:**
- 주 경계 계산: 일 23:59:59 / 월 00:00:00 KST, UTC 변환
- 회원 등록, 재활성화, 비활성화
- 같은 Discord ID 중복 방지

## Phase 2. 인증과 출석 — ✅ 완료 (2026-11-05)
- 모델: `verification`, `verification_review`, `attendance`, `club_policy`
- `app/image`: 다운로드(크기 제한 스트리밍), 디코딩 검증, EXIF 제거, SHA-256, pHash, 저장
- `VerificationService`(판정 규칙), `AttendanceService`(생성)
- `/인증` 명령, 결과 Embed
- 검토 대상이면 관리자 채널에 메시지만 게시(버튼은 Phase 4)
- 계획 변경:
  - `PolicyService`의 목표 조회와 초기 시드를 Phase 3에서 앞당겼다. 인증 결과에 "이번 주 N / 목표"를 보여주려면 필요하다.
  - pHash를 numpy로 직접 구현하고 `imagehash`는 테스트에서 결과 비교용으로만 쓴다. Docker 이미지가 1.04GB에서 492MB로 줄었다.

**완료 조건:** 텍스트나 이미지를 제출하면 DB에 저장된다. 규칙을 통과하면 출석이 생성되고, 중복 이미지는 REVIEW_REQUIRED가 된다.
**테스트:**
- 인증 형태: 텍스트 / 이미지 / 텍스트+이미지
- 입력 거절: 빈 입력, 짧은 텍스트, 미지원 형식, 용량 초과, 손상된 이미지
- 하루 중복: 같은 날 재인증 차단, 거절 후 재인증 허용, 동시 제출(유니크 인덱스)
- 중복 이미지: SHA-256 일치, pHash 유사(리사이즈·재압축 이미지)
- 비활성 회원 차단

## Phase 3. 조회와 통계 — ✅ 완료 (2026-11-05)
- `StatisticsService` (`PolicyService`의 목표 조회·시드는 Phase 2에서 구현)
- `/내출석`, `/내기록`(페이지네이션), `/랭킹`, `/목표`
- 계획 변경: `/랭킹`은 별도 파일 없이 `bot/commands/me.py`에 두었다. `/랭킹`과 `/목표`는 회원 역할이 없는 관리자도 쓸 수 있다.

**완료 조건:** 회원이 자기 주간 현황, 이력, 전체 현황을 볼 수 있다.
**테스트:**
- 주간 집계: 주 경계, 주중 탈퇴자 제외, 주중 가입자 포함
- 목표 정책: 적용일 기준 목표 선택, 지난주 목표가 바뀌지 않음

## Phase 4. 관리자 기능 — ✅ 완료 (2026-11-06)
- `/관리` 그룹: 회원목록, 검토목록, 인증상세, 출석취소, 목표설정(이번 주 적용 시 영향 미리보기와 확인)
- Persistent 검토 View(승인, 거절과 사유 모달, 상세), 처리 후 메시지 갱신
- `ReviewService`: 조건부 상태 전이, AuditLog
- 지난 결과 알림(`bot/notify.py`)
- 구현 메모:
  - 검토 버튼은 discord.py의 `DynamicItem`으로 만들었다. custom_id(`review:approve:12`)에 동작과 인증 번호를 담아, 재시작 후에도 예전 메시지의 버튼이 동작한다.
  - 승인된 인증의 검토 메시지와 `/관리 인증상세`에도 "출석 취소" 버튼을 둔다(사유 필수 모달).
  - 지난 결과 알림은 먼저 "알림 완료"를 기록한 뒤 보낸다. 중복 전달은 없고, 전송 실패 시 그 알림은 `/내기록`에서만 볼 수 있다.

**완료 조건:** 관리자가 Discord만으로 검토, 승인, 거절, 출석 취소, 목표 변경을 할 수 있다.
**테스트:**
- 검토 처리: 승인 시 출석 생성, 거절 시 사유 저장
- 동시 처리: 두 관리자가 동시에 처리하면 한 명만 성공
- 출석 취소: 취소 후 통계 감소, 취소 후 같은 날 재인증
- 기록: AuditLog 기록, 지난 결과 알림이 한 번만 전달됨

## Phase 5. 자동화와 운영 — ✅ 완료 (2026-11-06)
- 주간 리포트(선점, 게시, 스냅샷, 놓친 게시 보충), `/관리 주간통계`, `/관리 주간리포트`
- 이미지 정리 작업
- `/관리 시스템상태` 완성
- Docker Compose 배포 구성, `pg_dump` 백업 스크립트
- `README.md`(설치·운영), `COMMANDS.md`(회원용 안내)
- 구현 메모:
  - 백업은 `scripts/backup.sh`(pg_dump + gzip, 14일 보관)와 `scripts/restore.sh`. 사진은 30일 보관 자료라 백업하지 않는다.
  - 이미지 정리는 삭제에 성공한(또는 이미 없던) 파일만 `image_path`를 비운다. 실패한 파일은 다음 날 다시 시도한다.
  - 주기 작업은 `setup_hook`에서 시작한다. 테스트에서 코그만 등록할 때는 돌지 않는다.

**완료 조건:** 관리자의 개입 없이 한 주가 돌아가고, 월요일에 리포트가 한 번만 게시된다.
**테스트:**
- 리포트: 게시와 중복 방지, 재시작 후 보충
- 이미지 정리: 보관 기간 경과 파일 정리 후에도 해시 중복 탐지 유지
- 전체 흐름: 인증 → 검토 → 승인 → 통계 → 리포트
