# 헬스클럽 Discord 자동 출석 관리 — 요구사항 명세 (v2)

> 원본 명세(v1)를 리뷰한 뒤 확정한 정책을 반영한 문서다.
> v1과 달라진 결정과 그 이유는 `docs/adr/`에 기록한다.

## 1. 개요

- 형태: Discord Bot 하나(단일 프로세스)가 모든 기능을 제공한다.
- 규모: 회원 10~30명, Discord 서버 1개
- 인증 방식: `/인증` 명령어로 텍스트, 사진, 또는 둘 다 제출
- 검증 방식: **규칙 기반 자동 승인 + 관리자 사후 검토**. AI는 사용하지 않는다(ADR-0002).
- 시간대: 저장은 UTC(`timestamptz`), 날짜·주간 계산과 표시는 Asia/Seoul
- 주간 범위: 월요일 00:00 ≤ t < 다음 주 월요일 00:00 (KST)

## 2. 사용자와 권한 (ADR-0004)

Discord 역할이 권한의 유일한 기준이다. 역할 ID는 환경변수로 설정한다.

| 구분 | 기준 | 비고 |
|---|---|---|
| 회원 | `MEMBER_ROLE_ID` 역할 보유 | 역할을 받으면 자동 등록, 잃거나 서버를 나가면 비활성화 |
| 관리자 | `ADMIN_ROLE_ID` 역할 보유 | 관리자 명령은 실행할 때마다 역할을 다시 확인 |

- 관리자도 운동 인증을 하려면 회원 역할이 있어야 한다.
- 회원 데이터는 삭제하지 않는다. 비활성화되어도 기록은 보존한다.
- 다시 역할을 받으면 같은 회원 레코드가 ACTIVE로 복귀한다.
- Server Members Intent(특권 인텐트)를 켜야 한다.

## 3. 운동 인증 `/인증`

### 3.1 입력
- `내용`(텍스트, 선택), `사진`(첨부, 선택). 둘 중 하나 이상은 필수다.
- `VERIFICATION_CHANNEL_ID`를 설정하면 해당 채널에서만 사용할 수 있다.
- 모든 응답은 **본인에게만 보이는 메시지(ephemeral)**로 보낸다.

### 3.2 처리 순서
1. 즉시 `defer(ephemeral=True)`로 응답한다(3초 제한 대응).
2. 회원인지(역할 보유), ACTIVE 상태인지 확인한다.
3. 출석일을 계산한다: `workout_date = interaction 생성 시각의 KST 날짜` (ADR-0003)
4. 같은 출석일에 승인됐거나 검토 대기 중인 인증이 있으면 **"이미 오늘 인증했습니다"**로 응답하고 종료한다.
5. 입력값을 검증한다(아래 3.3).
6. 사진이 있으면 다운로드·검증 후 SHA-256과 pHash를 생성한다.
7. 규칙에 따라 판정한다(아래 3.4).
8. **하나의 트랜잭션**으로 다음을 저장한다.
   - 인증 원본
   - 판정 이력
   - 승인이면 출석 레코드
9. 결과를 본인에게 응답한다(승인 / 검토 대기 / 거절과 사유, 이번 주 진행 현황).
10. 검토 대기 판정이면 관리자 채널에 검토 요청을 게시한다.

입력값 오류(3.3에 해당)는 인증으로 저장하지 않고 오류 메시지만 응답한다. 사용자는 고쳐서 다시 제출하면 된다.

### 3.3 입력 검증 (저장 전 거절)
| 조건 | 응답 |
|---|---|
| 내용과 사진 모두 없음 | 하나 이상 입력하라는 안내 |
| 텍스트만 있고 공백 제외 `TEXT_MIN_LENGTH`(기본 10자) 미만 | 운동 내용을 조금 더 적어 달라는 안내 |
| 형식이 JPEG/PNG/WEBP가 아님 | 지원하지 않는 형식 안내 |
| `IMAGE_MAX_BYTES`(기본 10MB) 초과, 5천만 화소 초과 | 용량·해상도 초과 안내 |
| 내용이 1000자 초과 | 줄여 달라는 안내 (Discord 옵션에서도 제한) |
| 다운로드 실패, 이미지 디코딩 실패 | 다시 시도하라는 안내 |

형식은 첨부파일 메타데이터만 믿지 않는다. 실제 바이트를 Pillow로 디코딩해서 형식을 판별한다.

관리자 채널의 검토 요청에는 Discord 첨부 URL이 아니라 봇이 저장한 사진을 다시 올린다. 첨부 URL은 만료되기 때문이다.

### 3.4 판정 규칙
| 순서 | 조건 | 판정 |
|---|---|---|
| 1 | 이미지 SHA-256이 기존 인증 이미지와 완전히 일치 | REVIEW_REQUIRED |
| 2 | 이미지 pHash 해밍 거리 ≤ `PHASH_DISTANCE_THRESHOLD`(기본 4)인 기존 이미지 존재 | REVIEW_REQUIRED |
| 3 | 그 외 | APPROVED (출석 생성) |

- 비교 대상은 **모든 회원의 모든 기존 인증 이미지**다. 본인이 과거에 올린 사진을 재사용한 경우도 포함한다.
- 해시가 일치했다는 이유만으로 거절하지 않고 관리자 검토로 보낸다.
- 일치한 인증 ID와 해밍 거리는 판정 이력에 저장한다.

### 3.5 재제출
- 거절(REJECTED)된 날에는 같은 날 다시 인증할 수 있다.
- 승인 또는 검토 대기 상태가 있는 날에는 다시 인증할 수 없다. DB의 부분 유니크 인덱스로도 보장한다.

## 4. 결과 알림 (ADR-0005)

DM은 사용하지 않는다. 모든 알림은 해당 채널에서 본인에게만 보이는 메시지로 보낸다.

- 규칙 판정은 명령 처리 중에 끝나므로, 결과는 바로 그 응답에 담긴다.
- 관리자 검토나 출석 취소처럼 **나중에 결정된 결과**는 다음과 같이 전달한다.
  - 회원이 **다음에 아무 봇 명령어를 사용할 때** "📬 지난 인증 결과"로 함께 보낸다.
  - 보낸 뒤 `result_notified_at`을 기록해 중복 전달을 막는다.
  - `/내기록`에서는 항상 확인할 수 있다.
- 이번 주 목표를 달성하는 인증이면 응답에 축하 문구를 붙인다.

## 5. 회원 명령어

| 명령어 | 내용 | 공개 범위 |
|---|---|---|
| `/인증` | 운동 인증 제출 | 본인만 |
| `/내출석` | 이번 주 횟수/목표/남은 횟수/달성 여부/운동한 요일/진행률 | 본인만 |
| `/내기록` | 내 인증 이력(날짜, 내용 요약, 상태, 거절·취소 사유), 페이지당 5건 | 본인만 |
| `/랭킹` | 이번 주 전체 회원의 횟수와 달성 여부(달성 여부 중심으로 정렬) | 본인만 |
| `/목표` | 이번 주 목표, 예약된 다음 주 목표 | 본인만 |
| `/도움말` | 권한에 따라 회원용 또는 관리자용 안내 | 본인만 |

다른 회원의 인증 내용과 이미지는 관리자만 볼 수 있다.

| 명령어 | 내용 |
|---|---|
| `/관리 회원목록` | 회원, 상태, Discord ID, 가입일 |
| `/관리 검토목록` | REVIEW_REQUIRED 인증 목록과 버튼 |
| `/관리 인증상세 번호` | 인증 원문, 이미지, 판정 이력, 중복 탐지 결과, 승인·거절·출석취소 버튼 |
| `/관리 출석취소 번호 사유` | 승인된 인증의 출석을 취소 |
| `/관리 목표설정 횟수 [적용:다음주/이번주]` | 주간 목표 변경. 기본은 다음 주부터 적용 |
| `/관리 주간통계 [주]` | 회원 수, 총 인증 수, 달성 회원 수, 달성률, 회원별 횟수, 검토 대기 수 |
| `/관리 주간리포트 [게시]` | 지난주 리포트 미리보기. 아직 게시되지 않았다면 게시 |
| `/관리 시스템상태` | 봇 지연, DB 연결과 지연, 가동 시간, 검토 대기 수, 최근 리포트 게시 여부, 이미지 저장 용량 |

- **v1 대비 제거된 명령:** `/회원등록`, `/회원비활성화`(역할 기반으로 대체), `/인증승인`, `/인증거절`(버튼으로 통합)
- `/관리` 그룹에는 `default_member_permissions`를 지정해 일반 회원 화면에서 숨긴다. 실제 권한 판정은 실행 시점의 역할 확인으로 한다. 서버 관리자는 "서버 설정 → 연동"에서 관리자 역할에 명령어 사용을 허용해야 한다.

### 6.1 검토 처리
검토 요청은 `ADMIN_CHANNEL_ID` 채널에 Embed와 버튼으로 게시한다. Embed에는 다음이 들어간다.
- 회원, 제출 시각, 출석일, 내용, 이미지
- 판정 사유, 일치한 기존 인증 링크

버튼은 다음 세 가지다.
- **승인:** 사유 입력 모달(선택)
- **거절:** 사유 입력 모달(필수)
- **상세:** 인증 상세 보기

처리 규칙:
- 상태 변경은 `WHERE status='REVIEW_REQUIRED'` 조건부 UPDATE로 한다. 다른 관리자가 먼저 처리했다면 "이미 처리된 인증"으로 응답한다.
- 승인하면 같은 트랜잭션에서 출석을 생성한다. 출석일은 인증의 `workout_date`다(승인 시점이 아님).
- 처리 후 원래 검토 메시지의 버튼을 비활성화하고 처리 결과를 표시한다.
- 봇이 재시작되어도 버튼이 동작해야 한다(Persistent View).

### 6.2 출석 취소
- 처리 내용(한 트랜잭션):
  - 출석 → REVOKED
  - 인증 → REJECTED
  - 판정 이력 추가
  - AuditLog 기록
- 취소된 날이 아직 오늘이라면 회원은 다시 인증할 수 있다.
- 지난 주차의 출석을 취소해도 이미 게시된 리포트는 바뀌지 않는다(스냅샷). 실시간 통계에는 반영된다.

### 6.3 주간 목표 변경
- 다음 주 적용(기본): `effective_from = 다음 주 월요일`
- 이번 주 적용: `effective_from = 이번 주 월요일`
  - 확인 버튼을 누르기 전에 "현재 달성 N명 → 변경 후 M명"처럼 영향을 보여준다.
- 이전 정책은 삭제하지 않고 새 행을 추가한다. 주차별 목표는 `effective_from ≤ 주 시작일`인 정책 중 가장 최근에 만든 것을 쓴다.

## 7. 주간 집계

- **출석 횟수:** 해당 주 `workout_date`를 가진 `attendance.status='ACTIVE'` 행의 수. 하루 최대 1회다.
- **집계 대상 회원:** 주가 끝나는 시점에 활동 중인 회원.
  - 조건: `joined_at < 주 종료` AND (`deactivated_at IS NULL` OR `deactivated_at ≥ 주 종료`)
  - **주중에 탈퇴하거나 비활성화된 회원은 제외한다.**
  - 주중에 가입한 회원은 포함하고, 목표는 그대로 적용한다(비례 감소 없음).
- **달성:** `출석 횟수 ≥ 해당 주의 목표`
- 주간 횟수를 따로 저장하지 않고 매번 attendance에서 계산한다.

## 8. 주간 리포트

- 매주 월요일 09:00(KST) 이후 `REPORT_CHANNEL_ID`(공개 채널)에 지난주 리포트를 게시한다.
- 내용:
  - 기간과 목표
  - 집계 대상 회원 수, 총 출석 수
  - 달성 회원 수와 달성률
  - **회원별 횟수와 달성 여부(공개)**
  - 검토 대기 인증 수
- **중복 방지:** `weekly_report.week_start` UNIQUE. 먼저 행을 선점한 뒤 게시하고, 게시에 실패하면 다음 주기에 재시도한다.
- **놓친 게시 보충:** 봇이 월요일 09:00에 꺼져 있었다면, 켜진 직후 확인해서 게시한다.
- 게시할 때의 집계 결과를 `snapshot`(JSONB)으로 저장한다.

## 9. 이미지 처리와 보관

- Discord 첨부 URL은 만료되므로 **제출 즉시 다운로드**한다.
- 보관 방식:
  - 경로: `IMAGE_DIR/{yyyy}/{mm}/{verification_id}.{ext}` (Docker 볼륨, 연월은 KST 제출 시각 기준)
  - 휴대폰 사진의 회전 정보(EXIF Orientation)는 먼저 반영한 뒤 제거한다.
  - EXIF는 제거한 뒤 저장한다.
  - 보관 기간: 판정 확정 후 `IMAGE_RETENTION_DAYS`(기본 30일)
  - 매일 정리 작업이 파일을 삭제하고 `image_path`를 NULL로 바꾼다.
- **해시(SHA-256, pHash)는 영구 보관**하므로 파일을 삭제한 뒤에도 중복 탐지는 계속된다.
- pHash는 64비트 값을 16자리 소문자 hex로 저장한다. 비교는 애플리케이션에서 전수 비교한다(연 1만 건 수준).

## 10. 예외 상황 처리

| 상황 | 처리 |
|---|---|
| 명령 중복 실행(같은 interaction) | `interaction_id` UNIQUE |
| 같은 날 두 번 인증(연타, 동시 요청 포함) | 사전 조회 후 부분 유니크 인덱스 위반을 잡아 "이미 인증" 응답 |
| 동일·유사 이미지 재사용 | 3.4 규칙 → 관리자 검토 |
| 이미지 다운로드 실패, 형식·용량 오류 | 3.3 → 저장하지 않고 안내 |
| DB 연결 실패 | "잠시 후 다시 시도" 응답, 에러 로그. 제출이 저장되지 않았음을 명확히 알림 |
| 봇 재시작 | Persistent View로 버튼 복구, 시작 시 역할과 회원 동기화, 놓친 리포트 보충 |
| 검토 중 상태 변경(관리자 동시 처리) | 조건부 UPDATE, 0행이면 "이미 처리됨" |
| 봇 응답 메시지 삭제 | 데이터에 영향 없음(원본은 DB에 있음) |
| 주간 목표 변경 | 정책 이력과 적용일 기준 계산 |
| 주 경계(일요일 23:59:59 제출) | interaction 생성 시각 기준으로 일요일 출석. 처리 지연과 무관 |
| 출석 취소 후 통계 | 매번 attendance에서 계산하므로 자동 반영 |
| 회원 역할 제거, 서버 탈퇴 | 즉시 비활성화, 그 주 통계에서 제외 |
| Discord Rate Limit | discord.py 내장 처리에 맡김. 대량 발송 기능 없음 |
